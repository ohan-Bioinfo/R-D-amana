# Microbiology Dashboard — Interactivity Upgrades Design

**Date:** 2026-07-18
**Author:** Muhannad + Claude
**Status:** Approved for planning

## Goal

Make the microbiology dashboard feel like an interactive app **without leaving its
current architecture** — a single self-contained HTML file generated by
`build_dashboard_combined.py`, opened locally and shared as a file. Three
upgrades: click-to-cross-filter, shareable views + bookmarks, and a one-command
data refresh.

## Context & Constraints

- **Deployment (fixed):** runs on Muhannad's machine, shared as a file. **No
  server, no hosting, no backend.** Confirmed 2026-07-18.
- Because of that, three of the four originally-floated wants collapse:
  **shareable** is already solved (a self-contained HTML *is* maximally
  shareable); **live data** becomes a frictionless rebuild, not real-time; a
  **framework rebuild (React/Svelte) is explicitly out of scope** — YAGNI for a
  single shared file, and it would complicate the "one file" property.
- The dashboard is one HTML file with inline JS + vendored Plotly, emitted by
  `microbiology/scripts/build_dashboard_combined.py`. All interactivity is
  vanilla JS driving Plotly.
- **Central state model** (already exists, in the emitted `<script>`):
  ```
  state = { years:Set, date_from, date_to, compliance:Set, sector:Set,
            severity:Set, gso_category:Set, microbe:Set,
            pathogen_only:bool, repeat_only:bool, exclude_raw_meat:bool }
  ```
  `applyFilters()` is the single re-render entry point; it filters `ROWS` and
  calls `renderAll(rowsFiltered)`. Every chart goes through the `reactChart(id,
  traces, layout, config)` wrapper. Filter chips (`f_year`, `f_sector`,
  `f_gso_category`, `f_microbe`, `f_severity`, `f_compliance`) reflect `state`.
- **Non-negotiables:** micro-only commits (chemistry leak-check = 0); `node
  --check` on the emitted `<script>` must pass; the file stays fully
  self-contained (no new external requests).

## Feature 1 — Cross-filtering (click a chart → filter everything)

Wire Plotly `plotly_click` on the categorical charts so clicking an element
toggles the **matching existing** `state` dimension and calls `applyFilters()`.

| Chart (div id) | Click sets | Value source |
|---|---|---|
| `chart_gso_cat` | `state.gso_category` | clicked category label (`points[0].y`/`x`) |
| `chart_sector` | `state.sector` | clicked sector label |
| `chart_map` (bubble) | `state.sector` | bubble's sector (from customdata) |
| `top-microbes` | `state.microbe` | clicked organism |
| `chart_severity_month` | `state.severity` | clicked severity tier (if resolvable) |

**Behaviour:**
- Toggling reuses the *same* Set the manual chips write to, so after a click the
  corresponding chip renders `.active` and the filter-status pill / active-count
  updates — no separate code path.
- Clicking the same element again removes it from the Set (toggle off).
- **Reset all filters** already clears these Sets, so it clears cross-filters too.
- A one-line hint ("💡 click charts to filter") is added to the filter bar.

**Implementation shape:** a single helper
`crossFilter(dimSetName, value)` that toggles `state[dimSetName]` (a Set) by
`value`, re-syncs the chip UI for that dimension, and calls `applyFilters()`.
Click handlers are (re)attached inside each chart's render function after
`reactChart(...)`, using `node.removeAllListeners('plotly_click')` +
`node.on('plotly_click', …)` — the pattern already used by the tests drill-down.

**Out of scope (later pass):** `chart_chains` and `top-subtypes` have no
matching filter dimension (`state` has no `chain` or `sample_name`); wiring them
would need a new dimension + filter logic. Explicitly deferred.

## Feature 2 — Shareable views + bookmarks

**URL-hash sync (view persistence):**
- `serializeState() → string`: encode the non-default parts of `state` into a
  compact `location.hash` (e.g. `#y=2025&gso=Dairy%20Products&path=1`). Sets are
  joined by a separator; dates only when non-default.
- `deserializeState(hash)`: parse the hash back into `state` on page load
  (`DOMContentLoaded`), then `applyFilters()`.
- Write the hash on every `applyFilters()` (via `history.replaceState` so it
  doesn't spam browser history). A `hashchange` listener is **not** required.
- Works from a `file://` URL — hashes are local to the document.

**Copy view link:** a button in the filter/year bar that copies the current full
URL (including hash) to the clipboard via `navigator.clipboard.writeText`, with a
brief "copied ✓" confirmation. Reproduces the exact view for whoever opens the
same file with that link.

**Bookmarks bar:** a small row of one-click preset buttons that set a filter
combo and `applyFilters()`. Presets (approved):
1. **2025 · pathogens only** — `years={2025}, pathogen_only=true`
2. **Central sector** — `sector={Central}`
3. **Non-compliant only** — `compliance` Set = the non-compliant chip value
   (the exact token read from the existing `f_compliance` chips at build time)
4. **Ready-to-Eat foods** — `gso_category={Ready to Eat Foods}`

Each preset first clears `state`, then applies its combo. A preset button renders
`.active` when the current state matches it (best-effort exact match).

## Feature 3 — Frictionless data refresh

A single shell entry point `microbiology/scripts/refresh.sh` that runs the whole
pipeline end-to-end and rebuilds the dashboard, with clear per-step logging and
`set -e` fail-fast:

1. `clean_2024.py --year 2024`
2. `enrich_2024.py --year 2024`
3. `clean_2025.py`  *(2025 has no separate enricher; it goes straight to gso)*
4. `enrich_gso.py`  *(auto-iterates every `data<YEAR>.parquet`)*
5. `build_dashboard_combined.py`

It uses the repo venv (`microbiology/.venv/bin/python`) and prints a final
"dashboard refreshed → reports/microbiology_dashboard.html" line. A short
`scripts/README_refresh.md` documents usage and a `cron` snippet for scheduled
auto-refresh (the practical "live data" answer without a server).

## Data Flow

```
refresh.sh ──▶ parquets (cleaned/) ──▶ build_dashboard_combined.py ──▶ dashboard.html
                                                                          │
 user opens file ──▶ deserializeState(hash) ──▶ applyFilters() ──▶ renderAll()
                                                      ▲                    │
                       chip click / crossFilter() / bookmark ─────────────┘
                                                      │
                                          serializeState() ──▶ location.hash
```

All of Features 1–2 live in the emitted `<script>` (authored in
`build_dashboard_combined.py`'s `TEMPLATE`); Feature 3 is a new shell script.

## Error Handling / Edge Cases

- **Unknown hash values** (stale/edited link, renamed category): `deserializeState`
  ignores any token that doesn't match a known facet value — never throws; falls
  back to no filter for that dimension.
- **Cross-filter on a value not in the current filtered set:** allowed — it just
  narrows further or yields an empty view; the existing empty-state handling in
  each chart covers zero rows.
- **Clipboard API unavailable** (older/file:// quirk): fall back to selecting the
  URL text in a hidden input + `document.execCommand('copy')`; if that fails,
  show the link in a prompt.
- **`refresh.sh` step failure:** `set -euo pipefail` stops at the first failing
  step and prints which step failed; no partial silent build.

## Testing

- `node --check` on the extracted `<script>` after every rebuild (mandatory).
- Manual: click each wired chart → correct chip lights up, charts update, second
  click toggles off, Reset clears. Load a hash URL → view restores. Each bookmark
  → correct combo. Copy-link → clipboard holds the URL.
- `refresh.sh` runs clean end-to-end and reproduces the same sample counts
  (2024=9,316 / 2025=11,564).
- Micro-only commits: `git diff --cached --name-only | grep -c chemistry` = 0.

## Out of Scope

- Framework rebuild (React/Svelte), any backend/server, hosting, auth.
- Export (PDF/PNG/CSV) — deselected by user.
- Cross-filtering on chains and subtypes (no filter dimension yet) — later pass.
- Real-time/live data (no server) — refresh is a rebuild, not streaming.
