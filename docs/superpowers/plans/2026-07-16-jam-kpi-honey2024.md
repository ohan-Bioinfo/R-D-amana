# Jam KPI "not evaluated" + 2024 Honey Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop counting jam's no-validity tests as compliant (route them to a "Not evaluated" KPI bucket), and ingest the unread 2024 honey data to enable honey year-over-year.

**Architecture:** Part A adds a `not_evaluated` component to the precomputed test-count split for an explicit `DISPLAY_ONLY_SECTIONS = {"jam"}` set, surfaced in the test-banner JS. Part B adds a second year + an `only_sheets` whitelist to the honey schema so the cleaner reads the 2024 "Honey section" sheet.

**Tech Stack:** Python 3 (pandas, pyarrow, openpyxl), YAML schemas, self-contained HTML+JS dashboard. No test framework — tests are plain `assert` scripts run with the venv Python.

## Global Constraints

- Venv Python (absolute): `/home/bioinfo/Documents/Data-Analysis-Muhannad/microbiology/.venv/bin/python`. Referenced as `$PY`.
- Work in the isolated worktree `/home/bioinfo/Documents/Data-Analysis-Muhannad-chem-wt`; run python from its `chemistry/` dir; run `git` from the worktree root. Do NOT touch the main repo dir (concurrent microbio session).
- Scope: `chemistry/` + mirror `clean/chemistry/`. Never touch `microbiology/`.
- **Display-only detection is an explicit set `DISPLAY_ONLY_SECTIONS = {"jam"}`** — NOT "no `*_limit_value` columns" (aflatoxins/pesticides/water_analysis also have zero limit columns but real `is_valid` compliance; a column heuristic would wrongly zero their compliant counts).
- KPI invariant per section/year and aggregate: `compliant + non_compliant + not_evaluated == total`.
- `only_sheets: ["Honey"]` must read the 2025 file's `"Honey Section"` AND the 2024 file's `"Honey section"` and nothing else; honey-2025 output must be unchanged.
- All existing verify suites must still pass; mirror byte-identical.
